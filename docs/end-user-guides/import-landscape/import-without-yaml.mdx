# Import BTP Subaccount

In this guide, we take an assume an 
> already existing BTP Subaccount with 
>- numerous _entitlements_
>- a _service instance_
>- a worklaod runtime _(Kyma or CloudFroundry)_.

We **want to orchestrate them using the Crossplane BTP Provider** and control plane methodlogy.

We will achieve this by following these 3 steps

#### 1. Generate Yaml with Export CLI
We will use the CLI Exporter: BTP to **scan & generate the yaml definition** of cloud ressources that alredy exist in our already-running BTP Subaccount.

#### 2. Observe and Review
We will review the ressources and apply to BTP Crossplane Provider in observe mode. 
The provider will compare with the actual API in **read-only way and verify correctness of yaml.**

#### 3. Orchestrate from code
We can now make our yaml files the source of truth to **actively orchestrate** our cloud landscapes using the Crossplane BTP provider.


## Before you start

- Install [BTP CLI](https://tools.hana.ondemand.com/#cloud)
- ControlPlane running [BTP Crossplane Provider](../setup/install-provider-btp.mdx) and [authenticate](../setup/configure-provider-btp.mdx) subaccount

:::warning ensure Access

Make sure BTP provider's ProviderConfig uses a ServiceAccount that has admin access in the subaccount of interesst.

:::



## 0. Install the exporter

```bash
git clone https://github.com/SAP/crossplane-provider-btp.git
cd crossplane-provider-btp
go build -o btp-exporter ./cmd/exporter
./btp-exporter --help
./btp-exporter export --help
```

:::tip

For shell completion, run `./btp-exporter completion <shell> --help`.

:::

## 1. Generate resources

![import](/img/import-cli-yaml.png)

#### Login to BTP

Log in and target the global account containing your subaccount:

```bash
btp login --sso
btp target --global-account <global-account-subdomain>
```

<details>
<summary>Where to find <code>global-account-subdomain</code></summary>

1. Open the SAP BTP cockpit and choose **Switch Global Account**.
2. Find the global account containing your subaccount and copy its **Subdomain**.
3. Replace `<global-account-subdomain>` in the command above with that value.

See the [SAP BTP CLI reference](https://help.sap.com/docs/btp/btp-cli-command-reference/btp-login?locale=en-US) for more details.

</details>

#### Target subaccount

`btp-exporter` supports targeting your existing subaccount by name, by GUID, or interactively.

<Tabs groupId="btp-export-subaccount">
<TabItem value="pattern" label="By name" default>

Add `--subaccount '.*dev.*'` to the export command to select subaccounts whose display names contain `dev`. The pattern is a regular expression. 

```bash
./btp-exporter export \
  --subaccount '.*dev.*' \
  --kind subaccount \
  --output ../landscape.yaml
```

</TabItem>
<TabItem value="guid" label="By GUID">

Pass the subaccount GUID to select one specific subaccount. Replace `<subaccount-guid>` with the GUID of your existing subaccount.

```bash
./btp-exporter export \
  --subaccount '<subaccount-guid>' \
  --kind subaccount \
  --output ../landscape.yaml
```

</TabItem>
<TabItem value="interactive" label="Interactive">

Omit `--subaccount` from the export command. The exporter prompts you to choose your subaccount from an interactive list.

```bash
./btp-exporter export \
  --kind subaccount \
  --output ../landscape.yaml
```

</TabItem>
</Tabs>

#### Choose resources

Browser all available or only individual resources.

<Tabs groupId="btp-export-resources">
<TabItem value="all" label="All resources" default>

Use `--all` to export all supported resource kinds and their resources. 

_This only works if one single subaccount is targetted._

```bash {3}
./btp-exporter export \
  --subaccount '.*dev.*' \
  --all \
  --resolve-references \
  --output ../landscape.yaml
```

</TabItem>
<TabItem value="pick" label="Pick resources">

Use `--kind` to choose the resource kinds to export. This example exports `Subaccounts`, `Entitlements`, and `ServiceInstances`:

```bash {3-5}
./btp-exporter export \
  --subaccount '.*dev.*' \
  --kind subaccount \
  --kind entitlement \
  --kind serviceinstance \
  --resolve-references \
  --output ../landscape.yaml
```

</TabItem>
</Tabs>

:::tip Automatically resolve references

We encourage `--resolve-references` to be used as this uses Crossplane ressoure references, such as `subaccountRef`, instead of technical GUIDs to link the ressources meanignfully.

:::

## 2. Apply in observe mode

![observe](/img/import-cli-observe.png)

Apply the reviewed manifests directly to your control plane:

```bash
kubectl apply -f landscape.yaml
```

With `Observe`, Crossplane reads the existing resources without creating, updating, or deleting them.

### Verify observation

Check the resources you applied:

```bash
kubectl get managed
```

Apply the same gates to the deployed resources before enabling management:

## 3. Enable management

![orchestrate](/img/import-cli-observe-1.png)

Change `managementPolicies` from `[Observe]` to `["*"]` for each resource you want Crossplane to manage, keeping the IDs, names, credentials, and configuration verified during observation. The Subaccount example below highlights this change.

```yaml {8-9}
apiVersion: account.btp.sap.crossplane.io/v1alpha1
kind: Subaccount
metadata:
  name: demo-subaccount
  annotations:
    crossplane.io/external-name: "<subaccount-guid>"
spec:
  managementPolicies:
    - "*"
  providerConfigRef:
    name: default
  forProvider:
    displayName: Demo
    region: eu10
    subdomain: "<existing-subdomain>"
    subaccountAdmins:
      - "<verified-existing-admin>"
```

**`"*"` permits all supported actions, including creation, updates, and deletion.**

Re-apply the updated manifests:

```bash
kubectl apply -f landscape.yaml
```

After the control plane reconciles, verify the resource conditions and BTP state again before relying on active management.

## Troubleshooting

Rerun the export with `--verbose` for diagnostic output.

| Symptom | Check |
|---|---|
| Authentication or permission failure | Renew the session with `btp login --sso`, verify the targeted global account, and check subaccount permissions. The provider's credentials must also have access. |
| BTP CLI not found | Put `btp` on your `PATH`, or pass `--btp-cli /path/to/btp` to `export` (also configurable with `BTP_EXPORT_BTP_CLI_PATH`). |
| No resources returned | Check account access and selection patterns; try interactive selection to inspect available resources. |
