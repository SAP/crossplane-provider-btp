# Subaccount API credentials

`SubaccountApiCredential` publishes the XSUAA connection fields to the Secret
specified by `spec.writeConnectionSecretToRef`. Secret-based credentials must
contain these non-empty keys:

- `attribute.api_url`
- `attribute.client_id`
- `attribute.client_secret`
- `attribute.token_url`

Certificate-based credentials intentionally omit `attribute.client_secret`.

If the BTP credential exists but its connection Secret is missing or
incomplete, the managed resource reports `Synced=False` with the missing Secret
or field names. The provider leaves both the BTP credential and Secret
untouched. Restore the complete Secret at the currently configured reference;
the next observation will recover the resource without creating or rotating
the BTP credential.

The BTP API exposes `client_secret` only when the credential is created. The
provider cannot recover a lost old client secret from BTP. Structural
validation also does not prove that a complete Secret is current or accepted
by the OAuth endpoint.

If the BTP credential itself is absent, malformed Secret data does not prevent
normal recreation. Deletion likewise does not require the connection Secret
and is not blocked by missing or incomplete Secret data.
